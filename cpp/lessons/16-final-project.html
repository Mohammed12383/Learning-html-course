Final Project: Robot Arena

Time to put it all together. You'll build Robot Arena: choose a battle robot, and watch it fight a random opponent, round by round, with health bars and special attacks. It uses classes, inheritance, virtual functions, smart pointers, random numbers, loops and functions: everything from this course.

  • Planning a program
  • A base class and three robots

Play first

The Input box has two numbers: your robot (1 Tank, 2 Speedy, 3 Zapper) and a seed for the dice. Change them and press Run. Same seed, same battle. New seed, new battle.

Step 1: the plan

  1. Every robot has a name and health, can take damage, and can show a health bar. That's a base class: Robot.

  2. Each kind of robot attacks differently. That's a virtual function, attack(), that each derived class overrides.

  3. The player picks a robot. The enemy is random. Both are created with smart pointers.

  4. A loop runs rounds until one robot's health reaches 0.

Step 2: the dice

From lesson 15.

rng is a random generator shared by the whole program, and roll(low, high) is a small function that returns a random whole number in a range. Every attack uses it. The seed from the input makes the battle repeatable.

Step 3: the Robot base class

From lessons 12 and 13.

The data (name, health, maxHealth) is protected, so the derived robots can use it but nobody else can change it. kind() and attack() are pure virtual (= 0): Robot doesn't know how to attack, so every kind of robot must say how.

show() draws the health bar: health * 20 / maxHealth works out how many of the 20 bar pieces are full (integer division from lesson 3 is exactly right here), and string(n, '#') repeats a character.

Step 4: three kinds of robots

From lesson 13.

RobotHealthAttack
Tank1206 to 10, every time. Slow and steady.
Speedy80Hits twice: two rolls of 3 to 7.
Zapper904 to 8, but every third attack is a super zap: 18 to 25.

The Zapper has its own private charge counter. Each robot only writes what makes it different. Everything else comes from Robot.

Step 5: making robots with smart pointers

From lessons 10 and 15.

makeRobot returns a unique_ptr<Robot>: a smart pointer to some kind of Robot. The rest of the program doesn't care which kind. It just calls player->attack(), and the right version runs. When main ends, both robots are cleaned up automatically.

Step 6: the battle loop

From lessons 5 and 6.

The while loop keeps going while both robots are alive (&&). Each round, the player attacks; if the enemy survives, it hits back; then both health bars are shown. After the loop, an if checks who's still standing.

Make it yours

Ideas to remix Robot Arena

  1. Balance: change the health or attack numbers. Which robot is best? Try many seeds.
  2. A fourth robot: add a Healer that sometimes repairs itself instead of attacking (add a heal method to Robot).
  3. Critical hits: in the battle loop, a 1 in 10 chance (roll(1, 10) == 1) to do double damage.
  4. A tournament: put several robots in a vector<unique_ptr<Robot>> and let them fight one by one.
  5. Play it for real: compile it on your computer (lesson 15) and add a menu so the player chooses an action each round with cin.

What to learn next

  1. Set up C++ on a computer (lesson 15), so cin waits for you and programs can use files.

  2. Make games with graphics: raylib is a free, beginner-friendly library for 2D and 3D games in C++.

  3. Read more: learncpp.com is a free, very thorough C++ tutorial, and cppreference.com explains every part of the Standard Library.

  4. Practice puzzles: sites with programming challenges are a great way to get faster at thinking in C++.

In Robot Arena, why can player->attack() run Tank, Speedy or Zapper code?

The pointer's type is Robot, but attack() is virtual, so C++ runs the version of the actual robot it points at.
