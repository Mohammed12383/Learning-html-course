Errors & Debugging

Every programmer, even the best in the world, writes code with mistakes in it. Mistakes in code are called bugs, and finding and fixing them is called debugging. It's a skill, and you can learn it.

Three kinds of errors

syntax

Python can't read it. A missing bracket, quote or colon. Nothing runs at all.

runtime

It crashes while running. Dividing by zero, a name that doesn't exist. The program stops at that line.

logic

It runs, but the answer is wrong. No error message at all. These are the sneakiest.

How to find a bug

  1. Read the error message. The type and line number tell you most of the story. Check the line before it too.

  2. Print things. Add print() lines to see what's in your variables at each step. This is called print debugging, and professionals do it all the time.

  3. Explain it out loud. Explain your code line by line to a friend, or even a rubber duck. You'll often spot the mistake halfway through. (Programmers really call this rubber duck debugging.)

  4. Change one thing at a time, then run it again.

try and except: handling problems politely

Some errors aren't your fault. If you ask for a number and someone types "banana", int() crashes. Instead of crashing, you can catch the error and do something sensible:

try:try the risky code
except ValueError:if this error happens,
do this instead

Type "banana" first, then a number. If the code inside try works, the except part is skipped. If it fails with a ValueError, Python jumps to except instead of crashing.

except IndexError as e stores the error in e, so you can print its message.

Don't catch everything

Only use try for problems you expect, like bad input. If you wrap everything in try, real bugs get hidden, and they're much harder to find.

Remember

  • Syntax errors: Python can't read it. Runtime errors: it crashes. Logic errors: wrong answer.
  • Read the error type, the line, and the details. Check the line before too.
  • Use print() to look inside your variables.
  • try: … except SomeError: … handles problems you expect, like bad input.
