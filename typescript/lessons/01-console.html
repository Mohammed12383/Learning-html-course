console.log() shows things

The console is a place where programs write messages. Every web browser has one hidden in its developer tools, and in this course it's the Output box. console.log() writes a line there.

Text in quotes is called a string. You can use double quotes "...", single quotes '...' or backticks `...` (more about those in lesson 4). The semicolon ; marks the end of a line of code. TypeScript can often guess where lines end, but it's a good habit to write it.

Text, numbers and math

Without quotes, 5 + 3 is math, so you see 8. With quotes, it's just text. Put several things in one console.log with commas, and they're shown with spaces in between.

Comments

Comments are notes for humans. The computer ignores them. // starts a comment that lasts until the end of the line. /* ... */ can cover several lines.

Two kinds of mistakes

TypeScript programmers meet two kinds of errors:

type error

Found while you type, before running. Shown under the code with a red line. TypeScript is protecting you.

runtime error

Happens while running. The program crashes at that line, and the error appears in the output.

How to read an error

Every error tells you the line number and a message. Read the message slowly: "Property 'lgo' does not exist on type 'Console'. Did you mean 'log'?" says exactly what's wrong. In this course you also get a plain-language explanation.

Fix them one at a time. (Hint: a quote is missing, and capital letters matter.)

Common mistakes

  • Capital letters: Console.log or console.Log don't exist. It's console.log.
  • Missing quote or bracket: every " and ( needs a partner.
  • Curly quotes “like these” from a word processor or the iPad keyboard. Code needs straight quotes ". On an iPad, turn off Smart Punctuation in Settings → General → Keyboard.

When does TypeScript show a type error?

Type errors are found by checking the code, so you see them while typing. That's TypeScript's superpower.

Remember

  • console.log(...) shows things in the output. Commas show several things.
  • Strings go in quotes. End lines with ;.
  • // comment and /* comment */ are ignored.
  • Type errors appear while you type. Runtime errors appear when the program runs.
