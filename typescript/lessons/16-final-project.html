Final Project: Daybloom Tasks

In the HTML course you built Daybloom, a pretend planner app. Now you'll make part of it actually work: a colorful to-do list where you can add tasks, tick them off, filter them and delete them. It even remembers your tasks. It's a real app, built with everything from this course.

Use the finished app

Add a task, tick one off, try the filters, delete one. Then press Run: your tasks are still there, because they're saved in the browser.

Step 1: the big idea

Almost every app works the same way. The data lives in variables. The page is drawn from the data. When you click something, you change the data, and the page is drawn again:

you click or type (an event)
an action changes the data: addTask, toggleTask, deleteTask
the data is saved
render() draws the page from the data

The code is organized in exactly that order. Find each section in the code by its // ---------- comment.

Step 2: types for the data

From lessons 8 and 10.

A task is an interface with four properties. The filter is a literal type with exactly three allowed values, so a typo like "actve" is impossible.

Each task gets a unique id number, so the app can find exactly the right task when you click its button, even if two tasks have the same text.

Step 3: saving and loading

From lesson 15.

load() reads the saved tasks with localStorage and JSON.parse. If there's nothing saved yet, it returns three example tasks. save() does the opposite with JSON.stringify. Both are wrapped in try/catch, because some browsers block saving, and the app should still work.

Step 4: actions

From lessons 7 and 9.

Each action is a small function that changes the tasks array, then calls update():

  • addTask uses push and picks a pastel color in turn with %.
  • toggleTask uses find to get the task with that id and flips done with !.
  • deleteTask uses filter to keep every task except that id.

Step 5: drawing the page

From lesson 13.

render() empties the list, then builds one <li> for each visible task with createElement, sets its classes and color, and connects its buttons with addEventListener. If there are no tasks to show, it shows a friendly message instead. Finally it updates the counter and highlights the active filter button with classList.toggle.

The CSS in index.html does the styling: the done class crosses out the text and fills in the circle. TypeScript only switches the class on and off.

Make it yours

Ideas to remix Daybloom Tasks

  1. Your colors: change the COLORS array and the purple #8F7BFF in the CSS.
  2. Emoji picker: add a <select> next to the input with a few emoji, and add the chosen one to each new task.
  3. Edit tasks: double-click a task's text to change it (hint: the "dblclick" event and prompt, or an input).
  4. Due today: add a due?: string property and show it under the task.
  5. Celebrate: when the last task is ticked off, show a big "🎉 All done!" message.

Changes you make here are temporary. When you like your version, press Copy on each tab and keep it, or build it as a real project with Vite (lesson 15).

What to learn next

  1. Build your own small apps: a quiz, a habit tracker, a recipe box, a memory game. Use the same pattern: data, actions, render, events.

  2. Set up a real project on a computer with Vite (lesson 15) and put it online.

  3. Learn a framework: React is the most popular. It uses the same idea of drawing the page from data, but does the redrawing for you.

  4. Read the docs: the official handbook at typescriptlang.org/docs is excellent, and MDN Web Docs explains every DOM property.

In Daybloom Tasks, what happens after deleteTask changes the tasks array?

Data first, then draw. The page always shows what's in the tasks array.
