Generics & Collections

Some code works the same way for any type: "get the first item" works for a list of numbers and a list of names. Generics let you write it once and still keep the types. You'll also meet Map and Set, two very handy collections.

The problem

Imagine a function that returns the first item of an array. What type should it have? If you write number[], it only works for numbers. If you use any, TypeScript stops helping:

Generic functions

A generic function has a type parameter, written in angle brackets like <T>. Think of T as a blank that gets filled in with the real type each time you call the function:

TypeScript works out T from what you pass in. You've already used generics: number[] is short for Array<number>, and querySelector<HTMLButtonElement> on the course home page is a generic function too.

Generic interfaces

Map: look things up by key

A Map stores pairs: a key and a value. You find a value by its key, like looking up a word in a dictionary. Its type says what the keys and values are: Map<string, number>.

Counting with a Map

Set: no duplicates

A Set is a collection where every value appears only once. Adding something that's already there does nothing:

Record: an object with known key and value types

Record<Day, number> means "an object with exactly the keys mon, tue and wed, each holding a number". Leave one out, and TypeScript complains.

Remember

  • function f<T>(x: T): T: T is a type blank, filled in for each call.
  • interface Box<T> { contents: T }. Array<number> = number[].
  • new Map<K, V>(): set, get, has, size.
  • new Set<T>(): unique values. Record<K, V>: an object type.
