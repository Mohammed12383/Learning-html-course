Smarter Types

Real values aren't always just "a string" or "a number". A size might be "small", "medium" or "large", and nothing else. A user might be logged in, or might be nobody. TypeScript's type system can describe all of that exactly.

  • Union types: this or that
  • Literal types
  • Narrowing
  • null, undefined, ?. and ??
  • any vs unknown

null and undefined: "nothing"

Two special values mean "nothing here": undefined (never set) and null (set to nothing on purpose). They cause more bugs than anything else in JavaScript. TypeScript makes you handle them:

  • a?.b (optional chaining): if a is null or undefined, the result is undefined instead of a crash.
  • a ?? b (nullish coalescing): use a, but if it's null or undefined, use b instead.

any and unknown

any

Switches type checking off. Anything goes, so TypeScript can't help you. Avoid it.

unknown

"I don't know yet." Safe: TypeScript makes you check the type before using it.

Remember

  • A | B means A or B. Check with typeof to narrow it.
  • type Size = "s" | "m" | "l"; allows only those values.
  • Handle null/undefined with if, ?. and ??.
  • Prefer unknown over any.
