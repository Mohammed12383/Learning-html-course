Classes

A class is a blueprint for making objects that have both data and actions. One Player class can make as many players as you need, each with their own name and score. TypeScript adds private parts, so nothing outside the class can mess with what's inside.

A blueprint for objects

Think of it like this

A class is a cookie cutter. The cookies you make with it are objects (also called instances). Every cookie has the same shape, but each one can have different sprinkles.

  • Properties (name, age) are listed at the top, with their types.
  • The constructor runs automatically when you make a new object with new. It sets up the starting values.
  • this means "this particular object". this.name = name stores the name inside this dog.
  • Methods (bark, haveBirthday) are functions that belong to the object.

A shortcut: parameter properties

Writing each property three times (at the top, in the constructor brackets, and with this.x = x) is a lot of typing. TypeScript has a shortcut: put public (or private, or readonly) in front of a constructor parameter, and it becomes a property automatically:

private and readonly: protect the inside

Some data should only be changed by the class itself. Mark it private, and code outside the class can't touch it. readonly means it can never change after the constructor.

get balance() is a getter: it looks like a property from the outside (mine.balance, no brackets), but runs code inside. Others can read the balance, but only the class can change the coins. That's the whole point of private.

extends: a class based on another

A class can extend another: it gets everything from the parent class, and can add more or change some methods. super(...) calls the parent's constructor.

Notice Animal[]: a Cat and a Bird are both Animals, so they fit in the same array. Each one still uses its own speak.

implements: promise to match an interface

implements Drawable promises that the class has everything the interface lists. If you forget draw, TypeScript tells you.

Common mistakes

  • Forgetting new: Dog("Rex", 3) is an error. Write new Dog("Rex", 3).
  • Forgetting this.: inside a method, write this.name, not name.
  • Forgetting super() in a child class's constructor.

What does private mean on a property?

private keeps it inside the class. "Can never change" is readonly.

Remember

  • class Name { prop: type; constructor(...) { } method() { } }
  • new Name(...) makes an object. this is the current object.
  • constructor(public x: type) makes a property for you.
  • private, readonly, get. extends + super(). implements an interface.
