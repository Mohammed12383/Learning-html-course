Objects & Interfaces

A user has a name, an email and an age. A song has a title, an artist and a length. An object groups related values together under one name. An interface describes the shape an object must have, and TypeScript makes sure it does.

Many values, one name

An object is written with curly brackets. Inside are properties: a name, a colon, and a value.

petname: "Rex" age: 3 isGoodBoy: truean object

TypeScript remembers the shape of the object: it has name, age and isGoodBoy, nothing else. So adding color later is flagged. That catches typos like pet.nmae too.

interface or type?

You'll also see type User = { name: string; ... }. For describing objects, interface and type do almost the same thing. This course uses interface for object shapes and type for everything else (lesson 10).

Optional and read-only properties

  • A ? after the name makes a property optional. If it's missing, its value is undefined.
  • readonly means the property can be set when the object is made, but never changed after.

Common mistakes

  • = instead of : inside an object. It's { name: "Rex" }.
  • Forgetting commas between properties.
  • Missing a required property: TypeScript tells you which one.
  • Reading an optional property without checking: it might be undefined.

interface Pet { name: string; age?: number }. Which object is NOT allowed?

name is required. age has a ?, so it can be left out.

Remember

  • const o = { key: value, ... }; Read with o.key.
  • interface Name { prop: type; } describes an object's shape.
  • prop?: optional, readonly can't change.
  • Name[] is an array of objects. { ...o } copies, const { a } = o takes properties out.
