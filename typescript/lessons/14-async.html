Waiting: Timers & async

Lots of things on the web take time: a timer counting down, a photo uploading, data arriving from a server. TypeScript doesn't freeze while it waits. It carries on, and comes back when the thing is ready. This lesson shows how.

Do it later: setTimeout

setTimeout(function, milliseconds) runs a function once, after a delay. 1000 milliseconds is 1 second. Watch the order of the messages:

The program doesn't stop and wait at setTimeout. It sets the timer, carries on to the next line, and the timer's function runs later. This "carry on and come back later" idea is called asynchronous code (or async for short).

Common mistakes

  • Forgetting await: then you get the Promise itself, not the value. TypeScript usually notices, because the types don't match.
  • Using await outside an async function.
  • Seconds vs milliseconds: setTimeout(f, 2) waits 2 milliseconds, not 2 seconds. Use 2000.
  • Forgetting clearInterval: the interval keeps running forever.

In what order are these logged? log("A"); setTimeout(() => log("B"), 0); log("C");

Even with 0 milliseconds, the timer's function runs later, after the code that's running now has finished.

Remember

  • setTimeout(fn, ms) once later. setInterval(fn, ms) again and again, clearInterval(id) stops it.
  • A Promise<T> is a value that will be ready later.
  • async function f() { const x = await promise; } waits without freezing.
  • Use try { await ... } catch { ... } for things that can fail.
