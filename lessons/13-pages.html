Multiple Pages

A website is usually more than one page: Home, About, Contact. In this lesson you'll build a real three-page website with a menu that connects the pages and one CSS file that styles them all.

A website is a folder of files

Each page of a website is its own .html file. All the files live together in one folder:

little-leaf-cafe/
├── index.html      ← the home page (always called index.html)
├── about.html      ← the About page
├── contact.html    ← the Contact page
├── style.css       ← the design, shared by every page
└── images/
    ├── logo.png
    └── cake.jpg

When someone visits littleleafcafe.com, the browser automatically opens index.html. That's why the home page always has that name. The other pages have names you choose, and their address is the file name: littleleafcafe.com/about.html.

What to notice

  • The menu is copied onto every page. Each page needs its own menu so people can always move around.
  • The active class moves to a different link on each page. That's how the menu shows which page you're on.
  • Every page links to style.css. Change a color there once, and all three pages change.

One CSS file for the whole site

Until now, the CSS was inside a <style> tag on the page. For a website with several pages, put the CSS in its own file ending in .css, and connect each page to it with a <link> in the <head>:

<linktag
relrelationship
="stylesheet""this is my CSS"
hrefwhere
="style.css"the CSS file
>

A .css file contains only CSS rules, with no <style> tags around them. Look at the style.css tab in the playground above.

Why a separate file is better

  • Change once, update everywhere. A new brand color means editing one line, not ten pages.
  • Faster. The browser downloads the CSS once and remembers it for the other pages.
  • Tidier. HTML files hold content, the CSS file holds design.

Paths: finding files in folders

A path is directions from the current page to another file. It works for links, pictures and CSS files. Imagine this website:

my-website/
├── index.html
├── style.css
├── images/
│   └── cat.jpg
└── blog/
    └── first-post.html
FromToPathMeans
index.htmlstyle.cssstyle.cssSame folder: just the name.
index.htmlcat.jpgimages/cat.jpgGo into the images folder.
index.htmlfirst-post.htmlblog/first-post.htmlGo into the blog folder.
first-post.htmlindex.html../index.html.. means go up one folder.
first-post.htmlcat.jpg../images/cat.jpgUp one folder, then into images.

Think of it like this

A path is like giving directions in a building. images/cat.jpg means "go into the room called images and get cat.jpg". ../ means "go back out to the hallway first".

Putting your website online

Right now your website only lives on your computer. To let anyone in the world visit it, you put the folder on a web host: a computer that's always online. For simple HTML and CSS sites, there are great free options:

  1. Netlify Drop (easiest): go to app.netlify.com/drop and drag your website folder onto the page. In a few seconds you get a real web address you can share.

  2. GitHub Pages: put your files in a GitHub repository (like this course!). In the repository's Settings → Pages, choose your main branch and press Save. Your site appears at your-name.github.io/repository-name.

  3. Your own name: later, you can buy an address like yourname.com (about $10 to $15 a year) and connect it to Netlify or GitHub Pages.

Common mistakes

  • Wrong file name in the link: href="About.html" won't find about.html.
  • Forgetting rel="stylesheet" in the link tag, so the CSS doesn't load.
  • Putting <style> tags inside a .css file. A CSS file holds only the rules.
  • Forgetting ../ when a page inside a folder links to files outside it.

Remember

  • A website is a folder. The home page is index.html.
  • Link pages with <a href="about.html">. Put the menu on every page.
  • Share one design: <link rel="stylesheet" href="style.css"> in every head.
  • Paths: folder/file goes in, ../ goes up.
